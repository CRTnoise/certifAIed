Learning is fitting a functionL’apprentissage, c’est ajuster une fonction

  • Define model, parameter, lossDéfinir modèle, paramètre, perte
  • Supervised vs unsupervised vs reinforcementSupervisé, non supervisé, par renforcement
  • Train / validation / test splitDécoupage entraînement / validation / test

Classical programming: you write the rules, the computer applies them to data. Machine learning flips it: you give examples of inputs with the correct outputs, and the computer finds the rules. "Finding the rules" means choosing numbers inside a function.

The four words everything rests on

  • Data: examples. Each example has features (inputs, written x) and often a label (the correct answer, written y).
  • Model: a function ŷ = f(x; θ) that turns an input into a prediction. The shape of the function is fixed by you.
  • Parameters θ: the adjustable numbers inside the model. Learning means picking good values for them.
  • Loss: one number that says how wrong the predictions are. Lower is better. Learning is the search for parameters that make the loss small.

The simplest model is a straight line: ŷ = w·x + b. Two parameters: the slope w (the weight) and the offset b (the bias). A common loss for predicting numbers is the mean squared error:

MSE = (1/N) · Σ (ŷᵢ − yᵢ)²

Squaring makes every error positive and punishes big errors much more than small ones.

En programmation classique, vous écrivez les règles et l’ordinateur les applique aux données. L’apprentissage automatique (machine learning) inverse la logique : vous donnez des exemples d’entrées avec les bonnes sorties, et l’ordinateur trouve les règles. « Trouver les règles » veut dire choisir des nombres à l’intérieur d’une fonction.

Les quatre mots sur lesquels tout repose

  • Données : des exemples. Chaque exemple a des caractéristiques (features, les entrées, notées x) et souvent une étiquette (label, la bonne réponse, notée y).
  • Modèle : une fonction ŷ = f(x; θ) qui transforme une entrée en prédiction. La forme de la fonction, c’est vous qui la fixez.
  • Paramètres θ : les nombres ajustables à l’intérieur du modèle. Apprendre, c’est leur trouver de bonnes valeurs.
  • Perte (loss) : un seul nombre qui dit à quel point les prédictions sont fausses. Plus il est bas, mieux c’est. Apprendre, c’est chercher les paramètres qui rendent la perte petite.

Le modèle le plus simple est une droite : ŷ = w·x + b. Deux paramètres : la pente w (le poids, weight) et le décalage b (le biais, bias). Une perte courante pour prédire des nombres est l’erreur quadratique moyenne (MSE) :

MSE = (1/N) · Σ (ŷᵢ − yᵢ)²

Le carré rend chaque erreur positive et punit les grosses erreurs bien plus que les petites.

Why you hide part of your data

A model can score perfectly on data it has seen by memorising it. What you care about is generalisation: performance on new data. So you split:

  • Training set (~70–80%): the model learns from it.
  • Validation set (~10–15%): you use it to make choices (which model, which settings).
  • Test set (~10–15%): touched once at the very end, to report an honest score.

Settings you choose yourself, not learned from data (like the shape of the model), are called hyperparameters. Parameters are learned; hyperparameters are chosen.

Pourquoi cacher une partie de vos données

Un modèle peut obtenir un score parfait sur des données déjà vues en les mémorisant. Ce qui compte, c’est la généralisation : la performance sur des données nouvelles. On découpe donc :

  • Jeu d’entraînement (~70–80 %) : le modèle apprend dessus.
  • Jeu de validation (~10–15 %) : il sert à faire des choix (quel modèle, quels réglages).
  • Jeu de test (~10–15 %) : utilisé une seule fois, tout à la fin, pour annoncer un score honnête.

Les réglages que vous choisissez vous-même au lieu de les apprendre des données (comme la forme du modèle) s’appellent des hyperparamètres. Les paramètres sont appris ; les hyperparamètres sont choisis.

Gradient descent: walking downhillDescente de gradient : descendre la pente

  • Derivative and gradientDérivée et gradient
  • Learning rateTaux d’apprentissage
  • Batch, mini-batch, stochasticBatch, mini-batch, stochastique

In Lab 1 you moved the sliders by feel. With millions of parameters that is impossible. We need an automatic rule that says which way to move each parameter.

The derivative is a slope

The derivative of the loss with respect to a parameter tells you: if I nudge this parameter up a tiny bit, does the loss go up or down, and how fast? With many parameters, the list of all these derivatives is the gradient, written ∇L. It points in the direction where the loss rises fastest.

So go the other way:

θ ← θ − η · ∇L(θ)

η (eta) is the learning rate: the step size. It is the single most important hyperparameter in practice.

  • Too small: training crawls.
  • Too large: you overshoot the valley, bounce around, or blow up to infinity (divergence).
  • Right: fast, steady descent.

Dans le Lab 1, vous avez bougé les curseurs au jugé. Avec des millions de paramètres, c’est impossible. Il faut une règle automatique qui dit dans quel sens bouger chaque paramètre.

La dérivée est une pente

La dérivée de la perte par rapport à un paramètre répond à la question : si je pousse ce paramètre un tout petit peu vers le haut, la perte monte-t-elle ou descend-elle, et à quelle vitesse ? Avec plusieurs paramètres, la liste de toutes ces dérivées est le gradient, noté ∇L. Il pointe dans la direction où la perte monte le plus vite.

On va donc dans l’autre sens :

θ ← θ − η · ∇L(θ)

η (êta) est le taux d’apprentissage (learning rate) : la taille du pas. C’est en pratique l’hyperparamètre le plus important.

  • Trop petit : l’entraînement se traîne.
  • Trop grand : on dépasse la vallée, on rebondit, ou on part vers l’infini (divergence).
  • Bien choisi : une descente rapide et régulière.

How much data per step

  • Batch gradient descent: compute the gradient on the whole training set, then step. Accurate but slow.
  • Stochastic (SGD): one example per step. Noisy but cheap. The noise can even help escape small bumps.
  • Mini-batch: 32 to a few thousand examples per step. The standard choice because hardware processes a batch in parallel.

One full pass over the training set is an epoch.

Convex vs non-convex

The MSE of a straight line is a perfect bowl (convex): one bottom, and gradient descent always finds it. The models in the next unit give bumpy landscapes (non-convex) with many valleys. In practice, in very high dimensions most valleys turn out to be nearly as good as each other, which is why this simple rule works so well.

Combien de données par pas

  • Descente de gradient par batch (complète) : calculer le gradient sur tout le jeu d’entraînement, puis faire un pas. Précis mais lent.
  • Stochastique (SGD) : un exemple par pas. Bruité mais peu coûteux. Le bruit peut même aider à sortir des petites bosses.
  • Mini-batch : de 32 à quelques milliers d’exemples par pas. Le choix standard, car le matériel traite un batch en parallèle.

Un passage complet sur le jeu d’entraînement s’appelle une époque (epoch).

Convexe ou non convexe

La MSE d’une droite est un bol parfait (convexe) : un seul fond, que la descente de gradient trouve toujours. Les modèles de l’unité suivante donnent des paysages bosselés (non convexes) avec beaucoup de vallées. En pratique, en très grande dimension, la plupart des vallées s’avèrent presque aussi bonnes les unes que les autres, et c’est pour cela que cette règle simple marche si bien.

  • Softmax & cross-entropySoftmax et entropie croisée

A straight line can only draw straight boundaries. Real problems are curved. A neural network builds curved functions by stacking many simple units.

One neuron

z = w₁x₁ + w₂x₂ + … + b a = φ(z)

It is the line from Unit 1 with several inputs, followed by an activation function φ that bends the result.

Why the bend is essential: stacking linear functions gives another linear function. Ten layers without activation are mathematically one layer. The non-linearity is what lets depth add power.

Une droite ne sait tracer que des frontières droites. Les vrais problèmes sont courbes. Un réseau de neurones construit des fonctions courbes en empilant beaucoup d’unités simples.

Un neurone

z = w₁x₁ + w₂x₂ + … + b a = φ(z)

C’est la droite de l’Unité 1 avec plusieurs entrées, suivie d’une fonction d’activation φ qui courbe le résultat.

Pourquoi la courbure est essentielle : empiler des fonctions linéaires donne encore une fonction linéaire. Dix couches sans activation valent mathématiquement une seule couche. C’est la non-linéarité qui permet à la profondeur d’ajouter de la puissance.

Layers

Put many neurons side by side and you get a layer. In matrix form: a = φ(W·x + b), where W is a matrix holding every weight of the layer. Feed one layer's output into the next and you get a multi-layer perceptron (MLP): input layer → hidden layers → output layer. "Deep" learning just means many hidden layers.

The universal approximation theorem says one wide enough hidden layer can approximate any reasonable function. Depth is used because it gets there with far fewer neurons: early layers build simple pieces, later layers combine them.

Backpropagation

Gradient descent needs the derivative of the loss for every weight. The network is a chain of functions, and the chain rule says the derivative of a chain is the product of the local derivatives:

∂L/∂w = ∂L/∂a · ∂a/∂z · ∂z/∂w

Backpropagation runs the network forward to get the loss (forward pass), then walks backward, layer by layer, multiplying local derivatives and reusing them (backward pass). It costs about twice the forward pass, no matter how many weights. Frameworks such as PyTorch do this for you (autograd), but you must be able to explain it.

Outputs for classification

For K classes the last layer outputs K raw scores called logits. Softmax turns them into probabilities that sum to 1:

softmax(zᵢ) = e^zᵢ / Σⱼ e^zⱼ

The matching loss is cross-entropy: L = −log(p_correct). If the model gives the correct class probability 0.9, loss is 0.105. If it gives 0.01, loss is 4.6. It punishes confident mistakes very hard. Remember softmax and cross-entropy: they come back in almost every later unit.

# PyTorch: a 2-layer MLP classifier, full training step
import torch, torch.nn as nn
model = nn.Sequential(nn.Linear(784, 128), nn.ReLU(), nn.Linear(128, 10))
opt = torch.optim.SGD(model.parameters(), lr=0.1)
logits = model(x)                          # forward pass
loss = nn.functional.cross_entropy(logits, y)  # softmax + -log p inside
opt.zero_grad(); loss.backward(); opt.step()  # backward pass + gradient step

Les couches

Mettez beaucoup de neurones côte à côte et vous obtenez une couche. En forme matricielle : a = φ(W·x + b), où W est une matrice qui contient tous les poids de la couche. Envoyez la sortie d’une couche dans la suivante et vous obtenez un perceptron multicouche (MLP) : couche d’entrée → couches cachées → couche de sortie. L’apprentissage « profond » (deep learning) veut juste dire beaucoup de couches cachées.

Le théorème d’approximation universelle dit qu’une seule couche cachée assez large peut approcher n’importe quelle fonction raisonnable. On utilise de la profondeur parce qu’on y arrive avec beaucoup moins de neurones : les premières couches construisent des pièces simples, les suivantes les combinent.

La rétropropagation

La descente de gradient a besoin de la dérivée de la perte pour chaque poids. Le réseau est une chaîne de fonctions, et la règle de dérivation en chaîne dit que la dérivée d’une chaîne est le produit des dérivées locales :

∂L/∂w = ∂L/∂a · ∂a/∂z · ∂z/∂w

La rétropropagation (backpropagation) fait tourner le réseau vers l’avant pour obtenir la perte (passe avant), puis remonte couche par couche en multipliant les dérivées locales et en les réutilisant (passe arrière). Elle coûte environ deux fois la passe avant, quel que soit le nombre de poids. Les frameworks comme PyTorch le font pour vous (autograd), mais vous devez savoir l’expliquer.

Les sorties pour la classification

Pour K classes, la dernière couche produit K scores bruts appelés logits. Le softmax les transforme en probabilités dont la somme vaut 1 :

softmax(zᵢ) = e^zᵢ / Σⱼ e^zⱼ

La perte associée est l’entropie croisée (cross-entropy) : L = −log(p_correct). Si le modèle donne une probabilité de 0,9 à la bonne classe, la perte vaut 0,105. S’il donne 0,01, elle vaut 4,6. Elle punit très fort les erreurs commises avec assurance. Retenez softmax et entropie croisée : ils reviennent dans presque toutes les unités suivantes.

The bias–variance trade-off

Underfitting: the model is too simple, bad on training and validation. Overfitting: the model memorised the training set, including its noise; training loss is low but validation loss is high. The gap between the two curves is your overfitting alarm.

Fighting overfitting

  • More data or data augmentation (flips, crops, noise for images; paraphrases for text).
  • Weight decay (L2 regularisation): add λ·Σw² to the loss so large weights cost something. L1 (λ·Σ|w|) pushes weights to exactly zero.
  • Dropout: during training, randomly switch off a fraction (e.g. 10–50%) of neurons each step, so no neuron can rely on a specific partner. Turned off at inference time.
  • Early stopping: stop when validation loss stops improving.

Better optimisers

  • Momentum: keep a running average of past gradients, like a heavy ball that rolls through small bumps.
  • Adam: momentum plus a per-parameter step size scaled by how large that parameter's recent gradients were. The default for most deep learning. AdamW applies weight decay correctly and is the default for large language models later.
  • Learning-rate schedules: warm-up (start tiny, grow for the first steps) then decay (often cosine) toward zero.

Keeping gradients healthy

Backprop multiplies many local derivatives. If they are mostly below 1, the product shrinks to nothing in early layers (vanishing gradients). If mostly above 1, it explodes. Fixes you should be able to name:

  • ReLU-family activations (derivative is 1 on the positive side, unlike sigmoid's max of 0.25).
  • Careful initialisation (Xavier/Glorot, He) that keeps signal variance stable across layers.
  • Normalisation layers: rescale activations to mean 0, variance 1. BatchNorm normalises across the batch; LayerNorm normalises across the features of one example (does not depend on batch size).
  • Residual (skip) connections: output = x + F(x). The gradient has a direct highway back through the "+x" path. This is what made 100+ layer networks trainable (ResNet, 2015).
  • Gradient clipping: cap the gradient norm to stop explosions.
Debug ritual

Before a big run, try to overfit a single small batch. If the model cannot drive training loss near zero on 10 examples, there is a bug in the code, not a data problem.

Combattre le surapprentissage

  • Plus de données ou de l’augmentation de données (retournements, recadrages, bruit pour les images ; paraphrases pour le texte).
  • Weight decay (régularisation L2) : ajouter λ·Σw² à la perte pour que les grands poids coûtent quelque chose. L1 (λ·Σ|w|) pousse des poids exactement à zéro.
  • Dropout : pendant l’entraînement, éteindre au hasard une fraction (ex. 10–50 %) des neurones à chaque pas, pour qu’aucun neurone ne dépende d’un partenaire précis. Désactivé à l’inférence.
  • Arrêt précoce (early stopping) : s’arrêter quand la perte de validation ne s’améliore plus.

De meilleurs optimiseurs

  • Momentum : garder une moyenne glissante des gradients passés, comme une bille lourde qui roule par-dessus les petites bosses.
  • Adam : momentum plus un pas propre à chaque paramètre, ajusté selon la taille de ses gradients récents. Le choix par défaut dans la plupart des cas. AdamW applique correctement le weight decay et sera le choix par défaut pour les grands modèles de langage plus loin.
  • Plannings du taux d’apprentissage : warm-up (commencer minuscule et augmenter pendant les premiers pas) puis décroissance (souvent en cosinus) vers zéro.

Garder des gradients en bonne santé

La rétropropagation multiplie beaucoup de dérivées locales. Si elles sont surtout inférieures à 1, le produit fond jusqu’à rien dans les premières couches (disparition du gradient). Si elles sont surtout supérieures à 1, il explose. Les remèdes à savoir citer :

  • Des activations de la famille ReLU (dérivée 1 du côté positif, contre 0,25 au maximum pour la sigmoïde).
  • Une initialisation soignée (Xavier/Glorot, He) qui garde la variance du signal stable d’une couche à l’autre.
  • Des couches de normalisation : ramener les activations à une moyenne 0 et une variance 1. BatchNorm normalise sur le batch ; LayerNorm normalise sur les caractéristiques d’un seul exemple (ne dépend pas de la taille du batch).
  • Des connexions résiduelles (skip connections) : sortie = x + F(x). Le gradient a une autoroute directe à travers le chemin « +x ». C’est ce qui a rendu entraînables les réseaux de plus de 100 couches (ResNet, 2015).
  • Le gradient clipping : plafonner la norme du gradient pour éviter les explosions.

Byte-Pair Encoding (BPE)

  1. Start with every character (or byte) as its own token.
  2. Count every adjacent pair in the training text.
  3. Merge the most frequent pair into a new token and add it to the vocabulary.
  4. Repeat until you reach the target vocabulary size.

Frequent words end up as a single token; rare words split into known pieces. Working at the byte level means no input is ever "unknown". A token ID like 4012 is just a label; 4012 is not "close" to 4013. We need numbers where distance means something.

From one-hot to dense

A one-hot vector has as many slots as the vocabulary, all zero except a 1 at the token's ID. Every word is equally far from every other word. An embedding is a short dense vector (typically 256 to 8,192 numbers) learned so that tokens used in similar ways end up close together.

Mechanically, an embedding layer is a table with one row per token: shape vocab_size × d_model. Looking up row 4012 is the same as multiplying the one-hot vector by that matrix. The rows are parameters, trained with gradient descent like any weight.

Measuring closeness

cos(a, b) = (a · b) / (‖a‖ · ‖b‖) ∈ [−1, 1]

Cosine similarity compares direction only, ignoring length. 1 = same direction, 0 = unrelated, −1 = opposite. If vectors are normalised to length 1 first, cosine is just the dot product. Keep that in mind: the dot product is the star of Unit 8.

Un identifiant de token comme 4012 n’est qu’une étiquette ; 4012 n’est pas « proche » de 4013. Il nous faut des nombres où la distance veut dire quelque chose.

Du one-hot au dense

Un vecteur one-hot a autant de cases que le vocabulaire, toutes à zéro sauf un 1 à la position du token. Chaque mot est à la même distance de tous les autres. Un embedding (plongement) est un vecteur dense court (en général de 256 à 8 192 nombres), appris pour que les tokens utilisés de façon similaire se retrouvent proches.

Concrètement, une couche d’embedding est une table avec une ligne par token : de forme taille_vocab × d_model. Lire la ligne 4012 revient à multiplier le vecteur one-hot par cette matrice. Les lignes sont des paramètres, entraînés par descente de gradient comme n’importe quel poids.

Mesurer la proximité

cos(a, b) = (a · b) / (‖a‖ · ‖b‖) ∈ [−1, 1]

La similarité cosinus ne compare que la direction, pas la longueur. 1 = même direction, 0 = sans rapport, −1 = opposés. Si les vecteurs sont d’abord normalisés à une longueur de 1, le cosinus est simplement le produit scalaire. Gardez-le en tête : le produit scalaire est la vedette de l’Unité 8.

word2vec: learning embeddings from context

"You shall know a word by the company it keeps." word2vec (2013) trains a tiny network on a fake task: skip-gram predicts neighbouring words from a centre word; CBOW predicts the centre word from its neighbours. Nobody cares about the task; the learned embedding table is the prize. Negative sampling makes it cheap: instead of a softmax over the whole vocabulary, contrast the real neighbour with a few random words.

Directions in the space pick up meaning, which is why king − man + woman lands near queen. The same geometry also absorbs biases in the text (gender, ethnicity stereotypes), a known risk.

The limit: one vector per word

word2vec gives "bank" one vector whether it means river bank or money bank. Such embeddings are static. Units 8 and 9 show how to make them contextual: the vector for a token changes depending on the sentence around it.

Sentence embeddings and semantic search

You can also embed a whole sentence or paragraph into one vector (models such as Sentence-BERT, BGE, E5, or embedding APIs). Then:

  1. Embed every document once and store the vectors.
  2. Embed the user's query.
  3. Return the documents with the highest cosine similarity.

That is semantic search: it matches meaning, not exact keywords ("car" finds "automobile"). A database built to store vectors and find nearest neighbours fast is a vector database (FAISS library, Chroma, Qdrant, Milvus, pgvector). For millions of vectors they use approximate nearest neighbour indexes such as HNSW, trading a little accuracy for huge speed.

word2vec : apprendre des embeddings à partir du contexte

« On connaît un mot par les mots qu’il fréquente. » word2vec (2013) entraîne un tout petit réseau sur une fausse tâche : skip-gram prédit les mots voisins à partir du mot central ; CBOW prédit le mot central à partir de ses voisins. La tâche n’intéresse personne ; c’est la table d’embeddings apprise qui est le trésor. L’échantillonnage négatif (negative sampling) rend cela peu coûteux : au lieu d’un softmax sur tout le vocabulaire, on oppose le vrai voisin à quelques mots tirés au hasard.

Des directions de l’espace prennent un sens, c’est pourquoi roi − homme + femme atterrit près de reine. La même géométrie absorbe aussi les biais du texte (stéréotypes de genre, d’origine), un risque connu.

Embeddings de phrases et recherche sémantique

On peut aussi transformer une phrase ou un paragraphe entier en un seul vecteur (modèles comme Sentence-BERT, BGE, E5, ou des API d’embeddings). Ensuite :

  1. Calculer une fois l’embedding de chaque document et stocker les vecteurs.
  2. Calculer l’embedding de la requête de l’utilisateur.
  3. Renvoyer les documents avec la plus forte similarité cosinus.

C’est la recherche sémantique : elle trouve le sens, pas les mots-clés exacts (« voiture » trouve « automobile »). Une base conçue pour stocker des vecteurs et trouver vite les plus proches voisins est une base de données vectorielle (la bibliothèque FAISS, Chroma, Qdrant, Milvus, pgvector). The task: predict what comes next

A language model assigns probabilities to sequences. The standard way: predict the next token given the ones before it, then multiply:

P(t₁ … tₙ) = P(t₁) · P(t₂ | t₁) · P(t₃ | t₁, t₂) · …

Training is supervised learning with free labels: in any text, every next token is the label for the text before it. The loss is the cross-entropy from Unit 3 over the vocabulary. Perplexity = e^(average cross-entropy): roughly "how many tokens is the model hesitating between". Lower is better.

The oldest version is the n-gram model: count how often each token follows the previous n−1 tokens. It cannot see further than n−1 tokens back and cannot generalise to unseen combinations.

Recurrent neural networks

An RNN reads one token at a time and keeps a hidden state vector h, a running summary of everything so far:

hₜ = tanh(W_h · hₜ₋₁ + W_x · xₜ + b)

The same weights are reused at every step. Training "unrolls" the loop through time and backpropagates through it (backpropagation through time).

Two fatal weaknesses

  1. Forgetting. Gradients pass through the same multiplication at every step, so over long sequences they vanish (Unit 4). The model forgets the start of long sentences. LSTM (1997) and GRU add gates, small learned valves (forget, input, output) that decide what to keep in a separate memory cell. This helps a lot, but does not fully fix it.
  2. No parallelism. Step t needs step t−1. You cannot process token 500 before token 499, so training on GPUs, which love parallel work, is slow.

The bottleneck in translation

Early sequence-to-sequence models (2014) used an encoder RNN to read the source sentence into one final hidden vector, and a decoder RNN to generate the translation from that single vector. A whole sentence squeezed into one fixed-size vector: long sentences fell apart.

The question that sets up Unit 8

What if, at each output step, the decoder could look back at every encoder state and choose which ones are relevant right now, instead of relying on one compressed summary?

La tâche : prédire ce qui vient ensuite

Un modèle de langage attribue des probabilités à des séquences. La méthode standard : prédire le token suivant à partir des précédents, puis multiplier :

P(t₁ … tₙ) = P(t₁) · P(t₂ | t₁) · P(t₃ | t₁, t₂) · …

L’entraînement est de l’apprentissage supervisé avec des étiquettes gratuites : dans n’importe quel texte, chaque token suivant est l’étiquette du texte qui le précède. La perte est l’entropie croisée de l’Unité 3 sur le vocabulaire. La perplexité = e^(entropie croisée moyenne) : grosso modo « entre combien de tokens le modèle hésite ». Plus elle est basse, mieux c’est.

La version la plus ancienne est le modèle n-gramme : compter combien de fois chaque token suit les n−1 tokens précédents. Il ne voit pas plus loin que n−1 tokens en arrière et ne sait pas généraliser à des combinaisons jamais vues.

Les réseaux de neurones récurrents

Un RNN lit un token à la fois et garde un état caché h, un résumé courant de tout ce qu’il a lu :

hₜ = tanh(W_h · hₜ₋₁ + W_x · xₜ + b)

Les mêmes poids sont réutilisés à chaque pas. L’entraînement « déroule » la boucle dans le temps et rétropropage à travers elle (rétropropagation dans le temps).

Deux faiblesses fatales

  1. L’oubli. Les gradients traversent la même multiplication à chaque pas : sur de longues séquences, ils disparaissent (Unité 4). Le modèle oublie le début des phrases longues. Les LSTM (1997) et les GRU ajoutent des portes, de petites vannes apprises (oubli, entrée, sortie) qui décident quoi garder dans une cellule mémoire séparée. Ça aide beaucoup, sans tout régler.
  2. Pas de parallélisme. Le pas t a besoin du pas t−1. On ne peut pas traiter le token 500 avant le token 499, donc l’entraînement sur GPU, qui adore le travail en parallèle, est lent.

Le goulot d’étranglement en traduction

Les premiers modèles séquence-à-séquence (2014) utilisaient un RNN encodeur pour lire la phrase source et la résumer en un seul vecteur caché final, puis un RNN décodeur pour générer la traduction à partir de ce seul vecteur. Toute une phrase comprimée dans un vecteur de taille fixe : les phrases longues s’effondraient.

Attention answers Unit 7's question. For each position, compute a weighted average of information from all positions, where the weights are learned from how relevant each position is.

The library analogy

Each token produces three vectors, each by multiplying its embedding by a learned matrix:

  • Query q = x·W_Q: "what am I looking for?"
  • Key k = x·W_K: "what do I contain, as a label?"
  • Value v = x·W_V: "what I will hand over if you pick me."

Relevance of token j to token i = dot product qᵢ · kⱼ (Unit 6: dot product measures alignment). Softmax turns relevance scores into weights summing to 1 (Unit 3). The output for token i is the weighted sum of all values.

Attention(Q, K, V) = softmax( Q·Kᵀ / √dₖ ) · V

With all tokens stacked into matrices, this is two matrix multiplications and a softmax: fully parallel, which fixes the RNN speed problem.

Why divide by √dₖ

dₖ is the length of the key vectors. If the entries of q and k are roughly random with variance 1, their dot product has variance dₖ. With dₖ = 128 the scores are in the tens, softmax becomes nearly one-hot, and its gradient is almost zero, so learning stalls. Dividing by √dₖ brings the variance back to 1. Play with it in the lab.

L’attention répond à la question de l’Unité 7. Pour chaque position, on calcule une moyenne pondérée des informations de toutes les positions, où les poids sont appris selon la pertinence de chaque position.

L’analogie de la bibliothèque

Chaque token produit trois vecteurs, chacun en multipliant son embedding par une matrice apprise :

  • Requête (query) q = x·W_Q : « qu’est-ce que je cherche ? »
  • Clé (key) k = x·W_K : « qu’est-ce que je contiens, comme étiquette ? »
  • Valeur (value) v = x·W_V : « ce que je transmets si on me choisit ».

La pertinence du token j pour le token i = le produit scalaire qᵢ · kⱼ (Unité 6 : le produit scalaire mesure l’alignement). Le softmax transforme ces scores en poids dont la somme vaut 1 (Unité 3). La sortie du token i est la somme pondérée de toutes les valeurs.

Attention(Q, K, V) = softmax( Q·Kᵀ / √dₖ ) · V

Avec tous les tokens empilés en matrices, cela fait deux multiplications de matrices et un softmax : entièrement parallèle, ce qui règle le problème de vitesse des RNN.

Pourquoi diviser par √dₖ

dₖ est la longueur des vecteurs clés. Si les composantes de q et k sont à peu près aléatoires de variance 1, leur produit scalaire a une variance dₖ. Avec dₖ = 128, les scores montent à plusieurs dizaines, le softmax devient presque one-hot et son gradient est quasi nul : l’apprentissage cale. Diviser par √dₖ ramène la variance à 1. Self-attention vs cross-attention

  • Self-attention: Q, K and V all come from the same sequence. Every token updates itself using the others. This produces contextual embeddings: after one layer, "bank" in "river bank" and "bank account" already have different vectors. That solves the static-embedding limit of Unit 6.
  • Cross-attention: queries come from one sequence (the translation being written), keys and values from another (the source sentence). That is exactly the fix for the seq2seq bottleneck (Bahdanau attention, 2014).

The cost

Every token scores against every token: an n×n matrix. Compute and memory grow with n² in sequence length. Doubling the context quadruples attention cost. Remember this: it drives many engineering tricks in Unit 15.

def attention(Q, K, V, mask=None):   # Q,K,V: (n, d_k)
    scores = Q @ K.T / math.sqrt(K.shape[-1])   # (n, n) relevance
    if mask is not None:
        scores = scores.masked_fill(mask == 0, float("-inf"))
    weights = scores.softmax(dim=-1)             # each row sums to 1
    return weights @ V                           # weighted mix of values

Auto-attention ou attention croisée

  • Auto-attention (self-attention) : Q, K et V viennent tous de la même séquence. Chaque token se met à jour grâce aux autres. On obtient des embeddings contextuels : après une seule couche, « avocat » dans « avocat mûr » et « avocat au barreau » a déjà deux vecteurs différents. Cela règle la limite des embeddings statiques de l’Unité 6.
  • Attention croisée (cross-attention) : les requêtes viennent d’une séquence (la traduction en cours d’écriture), les clés et valeurs d’une autre (la phrase source). C’est exactement le remède au goulot seq2seq (attention de Bahdanau, 2014).

"Attention Is All You Need" (Vaswani et al., 2017) dropped recurrence entirely and built a network from attention plus pieces you already know from Units 3–4. This is the answer to "how does a transformer work?". Say it in this order.

1 · Positional encoding

Attention is a weighted sum; sums don't care about order. "dog bites man" and "man bites dog" would look identical. So we add position information to each token embedding:

  • Sinusoidal (original paper): fixed sine/cosine waves of different frequencies per dimension, so each position gets a unique pattern and relative offsets are easy to compute.
  • Learned absolute positions (GPT-2, BERT): one trainable vector per position.
  • RoPE (rotary, used by Llama, Mistral, Qwen): rotates q and k by an angle proportional to position, so their dot product depends on relative distance. Extends better to longer contexts.

2 · Multi-head attention

Instead of one attention with vectors of size d, run h heads in parallel, each with its own W_Q, W_K, W_V projecting to size d/h. Concatenate the results and mix them with an output matrix W_O. Same total cost as one big head.

Why: one softmax can only focus in one "way" at a time. Different heads learn different relations: one tracks the previous token, one links pronouns to nouns, one follows syntax. It is like several readers each looking for something different.

« Attention Is All You Need » (Vaswani et al., 2017) a abandonné toute récurrence et construit un réseau avec de l’attention et des pièces que vous connaissez déjà (Unités 3–4). C’est la réponse à « comment fonctionne un transformer ? ». Dites-la dans cet ordre.

1 · L’encodage positionnel

L’attention est une somme pondérée ; une somme se moque de l’ordre. « le chien mord l’homme » et « l’homme mord le chien » seraient identiques. On ajoute donc une information de position à chaque embedding de token :

  • Sinusoïdal (article d’origine) : des ondes sinus/cosinus fixes de fréquences différentes selon la dimension, pour que chaque position ait un motif unique et que les décalages relatifs soient faciles à calculer.
  • Positions absolues apprises (GPT-2, BERT) : un vecteur entraînable par position.
  • RoPE (rotary, utilisé par Llama, Mistral, Qwen) : fait tourner q et k d’un angle proportionnel à la position, pour que leur produit scalaire dépende de la distance relative. S’étend mieux aux contextes longs.

2 · L’attention multi-têtes

Au lieu d’une seule attention avec des vecteurs de taille d, on fait tourner h têtes en parallèle, chacune avec ses propres W_Q, W_K, W_V qui projettent en taille d/h. On concatène les résultats et on les mélange avec une matrice de sortie W_O. Même coût total qu’une seule grande tête.

Pourquoi : un seul softmax ne peut se concentrer que d’« une » façon à la fois. Des têtes différentes apprennent des relations différentes : l’une suit le token précédent, une autre relie les pronoms aux noms, une autre suit la syntaxe. Comme plusieurs lecteurs qui cherchent chacun autre chose.

3 · The causal mask

For a model that generates text left to right, token i must not see tokens after it, or next-token prediction becomes cheating. Before softmax, set the scores above the diagonal to −∞; they become 0 after softmax. This lets the model train on every position of a sequence in one parallel pass while still only looking backward.

4 · The block

x = x + MultiHeadAttention(LayerNorm(x))   # tokens exchange information
x = x + FeedForward(LayerNorm(x))          # each token thinks alone
  • Feed-forward network (FFN / MLP): two linear layers with an activation (GELU or SwiGLU), applied to each token independently. Usually 4× wider inside. Holds about two-thirds of the parameters; much of the model's stored "knowledge" lives here.
  • Residual connections (Unit 4): each sub-layer adds to a residual stream instead of replacing it.
  • LayerNorm (Unit 4), usually placed before each sub-layer (pre-norm) for stable training. Many modern models use the cheaper RMSNorm.

Attention moves information between tokens; the FFN processes information within each token. Stack N identical blocks (12 for GPT-2 small, 80+ for large models).

5 · In and out

Tokens → embedding table (Unit 6) + positions → N blocks → final LayerNorm → a linear layer to vocabulary size (the LM head, often sharing weights with the embedding table) → softmax → probability of each next token.

"Text is split into tokens, each mapped to a learned embedding plus position information. The sequence goes through a stack of identical blocks. 3 · Le masque causal

Pour un modèle qui génère du texte de gauche à droite, le token i ne doit pas voir les tokens suivants, sinon prédire le token suivant devient de la triche. Avant le softmax, on met les scores au-dessus de la diagonale à −∞ ; ils deviennent 0 après le softmax. Le modèle peut ainsi s’entraîner sur toutes les positions d’une séquence en une passe parallèle tout en ne regardant qu’en arrière.

x = x + MultiHeadAttention(LayerNorm(x))   # tokens exchange information
x = x + FeedForward(LayerNorm(x))          # each token thinks alone
  • Réseau feed-forward (FFN / MLP) : deux couches linéaires avec une activation (GELU ou SwiGLU), appliquées à chaque token indépendamment. Généralement 4× plus large à l’intérieur. Contient environ deux tiers des paramètres ; une bonne partie des « connaissances » stockées du modèle se trouve ici.
  • Connexions résiduelles (Unité 4) : chaque sous-couche ajoute au flux résiduel (residual stream) au lieu de le remplacer.
  • LayerNorm (Unité 4), en général placée avant chaque sous-couche (pre-norm) pour un entraînement stable. Beaucoup de modèles récents utilisent RMSNorm, moins coûteuse.

L’attention fait circuler l’information entre les tokens ; le FFN traite l’information à l’intérieur de chaque token. On empile N blocs identiques (12 pour GPT-2 small, plus de 80 pour les grands modèles).

A large language model (LLM) is a decoder-only transformer (Unit 9) with billions of parameters, trained on next-token prediction (Unit 7) over trillions of tokens of text and code.

Pre-training

  • Data: web crawls (Common Crawl), books, code, papers, cleaned by deduplication, quality and toxicity filters, language ID. Data quality matters as much as size.
  • Compute: thousands of GPUs for weeks. A rule of thumb: training compute ≈ 6 × parameters × tokens (FLOPs).
  • Result: a base model (or foundation model). It continues text; it does not follow instructions yet. Ask it a question and it may answer with more questions.

Scaling laws

Kaplan et al. (2020) showed loss falls smoothly and predictably as a power law in parameters, data and compute. Chinchilla (Hoffmann et al., 2022) found the compute-optimal ratio is about 20 training tokens per parameter; earlier models were too big for their data. Modern small models are deliberately "over-trained" far past that ratio because they are cheaper to run afterwards.

Some abilities (multi-step arithmetic, following examples in the prompt) appear only at larger scale: emergent abilities. In-context learning: the model picks up a task from examples in the prompt without any weight change (few-shot; with no examples, zero-shot).

Decoding: turning probabilities into text

At each step the model outputs a probability for every token. You pick one, append it, and run again: autoregressive generation.

  • Greedy: always take the most likely. Deterministic, often repetitive.
  • Beam search: keep the k best partial sequences. Good for translation, bland for chat.
  • Temperature T: divide logits by T before softmax. T<1 sharpens (safer), T>1 flattens (more creative, more errors). T→0 equals greedy.
  • Top-k: sample only among the k most likely tokens.
  • Top-p (nucleus): sample among the smallest set whose probabilities add up to p (e.g. 0.9). Adapts to how confident the model is.

Un grand modèle de langage (LLM, large language model) est un transformer décodeur seul (Unité 9) avec des milliards de paramètres, entraîné à prédire le token suivant (Unité 7) sur des milliers de milliards de tokens de texte et de code.

Le pré-entraînement

  • Données : collectes du web (Common Crawl), livres, code, articles, nettoyés par déduplication, filtres de qualité et de toxicité, détection de langue. La qualité des données compte autant que leur volume.
  • Calcul : des milliers de GPU pendant des semaines. Ordre de grandeur : calcul d’entraînement ≈ 6 × paramètres × tokens (en FLOP).
  • Résultat : un modèle de base (ou modèle de fondation). Il continue du texte ; il ne suit pas encore d’instructions. Posez-lui une question et il peut répondre par d’autres questions.

Les lois d’échelle

Kaplan et al. (2020) ont montré que la perte baisse de façon régulière et prévisible, selon une loi de puissance, avec les paramètres, les données et le calcul. Chinchilla (Hoffmann et al., 2022) a trouvé que le ratio optimal en calcul est d’environ 20 tokens d’entraînement par paramètre ; les modèles précédents étaient trop gros pour leurs données. Les petits modèles récents sont volontairement « sur-entraînés » bien au-delà de ce ratio, parce qu’ils coûtent ensuite moins cher à faire tourner.

Certaines capacités (arithmétique en plusieurs étapes, suivre des exemples donnés dans le prompt) n’apparaissent qu’à grande échelle : ce sont les capacités émergentes. L’apprentissage en contexte (in-context learning) : le modèle comprend une tâche à partir d’exemples dans le prompt, sans changer ses poids (few-shot ; sans exemple, zero-shot).

Le décodage : transformer des probabilités en texte

À chaque pas, le modèle produit une probabilité pour chaque token. On en choisit un, on l’ajoute, et on recommence : c’est la génération autorégressive.

  • Glouton (greedy) : toujours prendre le plus probable. Déterministe, souvent répétitif.
  • Recherche en faisceau (beam search) : garder les k meilleures séquences partielles. Bien pour la traduction, fade pour la conversation.
  • Température T : diviser les logits par T avant le softmax. T<1 affûte (plus sûr), T>1 aplatit (plus créatif, plus d’erreurs). T→0 revient au glouton.
  • Top-k : ne tirer qu’entre les k tokens les plus probables.
  • Top-p (noyau, nucleus) : tirer dans le plus petit ensemble dont les probabilités cumulées atteignent p (ex. 0,9). S’adapte à la confiance du modèle.

Turning a base model into an assistant happens in stages, usually called post-training or alignment.

Stage 1 · Supervised fine-tuning (SFT)

Continue training on tens of thousands of high-quality (instruction, ideal answer) pairs, written by people or by stronger models. Same next-token loss, but usually computed only on the answer tokens. Conversations are wrapped in a chat template with special role tokens (system, user, assistant). Result: an instruct or chat model.

Stage 2 · Preference tuning

It is easier for people to say which of two answers is better than to write the perfect one.

  • RLHF (reinforcement learning from human feedback, the InstructGPT recipe): collect pairs ranked by humans → train a reward model that scores answers → optimise the LLM with reinforcement learning (Unit 1: maximise reward), typically PPO, with a penalty (KL divergence) for drifting too far from the SFT model so it does not "hack" the reward.
  • DPO (direct preference optimisation, 2023): skips the separate reward model and RL loop; a simple classification-style loss directly raises the probability of preferred answers over rejected ones. Simpler and stable; very common in open models.
  • RLAIF / Constitutional AI: an AI model, guided by written principles, provides the preference labels.
  • RL with verifiable rewards: for maths and code, the reward is simply "is the answer correct / do the tests pass". This is how reasoning models (OpenAI o-series, DeepSeek-R1 with GRPO) learn to write long chains of thought before answering.

Should you fine-tune?

Order of attempts in industry: good prompting → retrieval (Unit 12) → fine-tuning. Fine-tune to change behaviour, format or style, or to specialise a small model to replace a big one. Don't fine-tune just to add facts that change; retrieval handles that better.

Parameter-efficient fine-tuning (PEFT)

Full fine-tuning of a 7B model needs memory for weights, gradients and Adam's two extra values per parameter: over 100 GB. PEFT freezes the original weights and trains a small add-on.

LoRA (low-rank adaptation): for a frozen weight matrix W of shape d×k, learn the change as the product of two thin matrices:

W' = W + (α/r) · B·A B: d×r, A: r×k, r ≪ d

B starts at zero, so training starts exactly from the original model. Typically applied to the attention projections (W_Q, W_V…). After training you can merge B·A into W: no extra inference cost. Adapters are a few MB, so you can keep one per task and swap them.

QLoRA: keep the frozen base in 4-bit precision (see Unit 15) and train LoRA adapters on top. Fine-tuning a 7B model fits on a single consumer GPU. Tools: Hugging Face transformers + peft + trl, Unsloth, Axolotl.

Transformer un modèle de base en assistant se fait par étapes, qu’on appelle généralement post-entraînement ou alignement.

Étape 1 · Le fine-tuning supervisé (SFT)

On continue l’entraînement sur des dizaines de milliers de paires (instruction, réponse idéale) de bonne qualité, écrites par des humains ou par des modèles plus forts. Même perte du token suivant, mais généralement calculée seulement sur les tokens de la réponse. Les conversations sont mises en forme avec un modèle de chat (chat template) et des tokens de rôle spéciaux (système, utilisateur, assistant). Résultat : un modèle instruct ou de chat.

Étape 2 · L’alignement sur les préférences

Pour un humain, il est plus facile de dire laquelle de deux réponses est la meilleure que d’écrire la réponse parfaite.

  • RLHF (apprentissage par renforcement à partir de retours humains, la recette d’InstructGPT) : collecter des paires classées par des humains → entraîner un modèle de récompense qui note les réponses → optimiser le LLM par renforcement (Unité 1 : maximiser la récompense), typiquement avec PPO, avec une pénalité (divergence KL) s’il s’éloigne trop du modèle SFT, pour qu’il ne « triche » pas avec la récompense.
  • DPO (direct preference optimization, 2023) : se passe du modèle de récompense séparé et de la boucle RL ; une perte simple, façon classification, augmente directement la probabilité des réponses préférées par rapport aux rejetées. Plus simple et stable ; très courant dans les modèles ouverts.
  • RLAIF / Constitutional AI : un modèle d’IA, guidé par des principes écrits, fournit les étiquettes de préférence.
  • RL avec récompenses vérifiables : pour les maths et le code, la récompense est simplement « la réponse est-elle juste / les tests passent-ils ». C’est ainsi que les modèles de raisonnement (série o d’OpenAI, DeepSeek-R1 avec GRPO) apprennent à écrire de longues chaînes de réflexion avant de répondre.

Devriez-vous faire du fine-tuning ?

Ordre des tentatives dans l’industrie : bien prompter → la recherche documentaire (Unité 12) → le fine-tuning. On fait du fine-tuning pour changer le comportement, le format ou le style, ou pour spécialiser un petit modèle qui en remplace un gros. Pas pour ajouter des faits qui changent : la recherche documentaire s’en charge mieux.

Le fine-tuning économe en paramètres (PEFT)

Le fine-tuning complet d’un modèle 7B demande de la mémoire pour les poids, les gradients et les deux valeurs supplémentaires d’Adam par paramètre : plus de 100 Go. Le PEFT gèle les poids d’origine et entraîne un petit module ajouté.

LoRA (low-rank adaptation) : pour une matrice de poids gelée W de forme d×k, on apprend la modification comme le produit de deux matrices fines :

W' = W + (α/r) · B·A B: d×r, A: r×k, r ≪ d

B démarre à zéro, donc l’entraînement part exactement du modèle d’origine. On l’applique en général aux projections d’attention (W_Q, W_V…). Après l’entraînement, on peut fusionner B·A dans W : aucun surcoût à l’inférence. Les adaptateurs font quelques Mo, on peut donc en garder un par tâche et les échanger.

Two limits of any LLM

  • Context window: the maximum tokens it can read at once (prompt + answer). From 4k to over 1M today. Remember n² from Unit 8: long contexts are costly, and models attend less reliably to the middle ("lost in the middle").
  • Hallucination: the model is trained to produce plausible next tokens, not true ones. When it lacks the fact, it produces something that looks right. Its knowledge also stops at a training cutoff, and it has never seen your private data.

Prompt engineering that actually matters

  • System prompt: role, rules, output format, set once.
  • Be specific; give the model the context a new colleague would need.
  • Few-shot examples (Unit 10) for format and edge cases.
  • Chain-of-thought: ask it to reason step by step before answering; improves maths and logic.
  • Structured output: ask for JSON matching a schema; many APIs can enforce it.
  • Delimit inputs (XML tags, triple quotes) so data is not mistaken for instructions, which is also a first defence against prompt injection.

Retrieval-augmented generation

RAG (Lewis et al., 2020) means: before answering, search your documents and paste the relevant pieces into the prompt. The model answers from the evidence instead of from memory. It combines semantic search (Unit 6) with generation. Benefits: fresh data without retraining, private data, fewer hallucinations, and citations to the source.

Deux limites de tout LLM

  • La fenêtre de contexte : le nombre maximal de tokens qu’il peut lire d’un coup (prompt + réponse). De 4k à plus d’un million aujourd’hui. Souvenez-vous du n² de l’Unité 8 : les contextes longs coûtent cher, et les modèles prêtent moins bien attention au milieu (« lost in the middle »).
  • L’hallucination : le modèle est entraîné à produire des tokens suivants plausibles, pas vrais. Quand il n’a pas le fait, il produit quelque chose qui a l’air juste. Ses connaissances s’arrêtent aussi à une date de coupure d’entraînement, et il n’a jamais vu vos données privées.

Le prompt engineering qui compte vraiment

  • Prompt système : rôle, règles, format de sortie, fixés une fois.
  • Soyez précis ; donnez au modèle le contexte dont aurait besoin un nouveau collègue.
  • Exemples few-shot (Unité 10) pour le format et les cas limites.
  • Chaîne de raisonnement (chain-of-thought) : lui demander de raisonner étape par étape avant de répondre ; améliore les maths et la logique.
  • Sortie structurée : demander du JSON conforme à un schéma ; beaucoup d’API peuvent l’imposer.
  • Délimitez les entrées (balises XML, triples guillemets) pour que les données ne soient pas prises pour des instructions : c’est aussi une première défense contre l’injection de prompt.

La génération augmentée par recherche

Le RAG (retrieval-augmented generation, Lewis et al., 2020) consiste à chercher dans vos documents avant de répondre, et à coller les passages pertinents dans le prompt. Le modèle répond à partir des preuves au lieu de sa mémoire. On combine recherche sémantique (Unité 6) et génération. Avantages : des données fraîches sans réentraînement, des données privées, moins d’hallucinations, et des citations de la source.

The two halves

Indexing (offline): load documents → split into chunks (e.g. 300–1,000 tokens with 10–20% overlap, ideally along headings or paragraphs) → embed each chunk → store vectors + text + metadata (source, page, date) in a vector database.

Query (online): embed the question → retrieve top-k chunks → optionally rerank → build the prompt ("Answer only from the context; say you don't know otherwise; cite sources") → generate.

What makes RAG good rather than a demo

  • Hybrid search: combine vector search with keyword search (BM25). Vectors catch meaning; keywords catch exact part numbers, error codes and names.
  • Reranking: retrieve 20–50 candidates fast, then re-score them with a cross-encoder (a model that reads the query and chunk together, like BERT from Unit 9). Slower but much more precise. Keep the best 3–5.
  • Query rewriting: turn a vague follow-up ("and the other one?") into a standalone question; or generate a hypothetical answer and search with it (HyDE).
  • Metadata filters: restrict by machine, date, access rights.
  • Variants you may hear: GraphRAG (retrieve over a knowledge graph), agentic RAG (the model decides when and what to search; Unit 13).

RAG failure has two places to look: retrieval (the right chunk was never found) or generation (it was found but ignored or misread). Measure them separately; Unit 16 shows how.

Les deux moitiés

L’indexation (hors ligne) : charger les documents → les découper en chunks (ex. 300–1 000 tokens avec 10–20 % de chevauchement, idéalement selon les titres ou les paragraphes) → calculer l’embedding de chaque chunk → stocker vecteurs + texte + métadonnées (source, page, date) dans une base vectorielle.

La requête (en ligne) : calculer l’embedding de la question → récupérer les top-k chunks → éventuellement les reclasser → construire le prompt (« Réponds uniquement à partir du contexte ; dis que tu ne sais pas sinon ; cite tes sources ») → générer.

Ce qui fait un bon RAG plutôt qu’une démo

  • Recherche hybride : combiner recherche vectorielle et recherche par mots-clés (BM25). Les vecteurs captent le sens ; les mots-clés attrapent les références de pièces, codes d’erreur et noms exacts.
  • Reranking (reclassement) : récupérer vite 20–50 candidats, puis les renoter avec un cross-encoder (un modèle qui lit la question et le chunk ensemble, comme BERT de l’Unité 9). Plus lent mais bien plus précis. Garder les 3–5 meilleurs.
  • Reformulation de requête : transformer une relance vague (« et l’autre ? ») en question autonome ; ou générer une réponse hypothétique et chercher avec elle (HyDE).
  • Filtres de métadonnées : restreindre par machine, date, droits d’accès.
  • Variantes que vous entendrez : GraphRAG (recherche sur un graphe de connaissances), RAG agentique (le modèle décide quand et quoi chercher ; Unité 13).

Quand un RAG échoue, il y a deux endroits où regarder : la recherche (le bon chunk n’a jamais été trouvé) ou la génération (il a été trouvé mais ignoré ou mal lu). Mesurez-les séparément ; l’Unité 16 montre comment.

Tool calling

You describe functions to the model (name, description, JSON schema of arguments). Instead of plain text, the model can reply "call get_machine_status with {"line": 3}". Your code executes it and sends the result back; the model continues. The model never runs anything itself: it only writes structured requests. This is function calling, and it is how LLMs reach calculators, databases, APIs and robots.

What makes it an agent

An agent is an LLM in a loop that decides its own next step until the goal is reached. The classic pattern is ReAct (Reason + Act, 2022): Thought → Action (tool call) → Observation (result) → Thought → … → Final answer. Add memory (short-term: the conversation; long-term: facts saved to a store and retrieved later) and planning (break the goal into steps first).

L’appel d’outils

Vous décrivez des fonctions au modèle (nom, description, schéma JSON des arguments). Au lieu de texte simple, le modèle peut répondre « appelle get_machine_status avec {"line": 3} ». Votre code l’exécute et renvoie le résultat ; le modèle continue. Le modèle n’exécute jamais rien lui-même : il écrit seulement des demandes structurées. C’est l’appel de fonctions (function calling), et c’est ainsi que les LLM atteignent calculatrices, bases de données, API et robots.

Ce qui en fait un agent

Un agent est un LLM dans une boucle qui décide lui-même de l’étape suivante jusqu’à atteindre le but. Le schéma classique est ReAct (Reason + Act, 2022) : Pensée → Action (appel d’outil) → Observation (résultat) → Pensée → … → Réponse finale. On ajoute de la mémoire (court terme : la conversation ; long terme : des faits enregistrés dans un stockage et retrouvés plus tard) et de la planification (découper d’abord le but en étapes).

Convolutional neural networks

A CNN slides small learned filters (e.g. 3×3) across an image. Early filters detect edges, later ones textures, parts, objects. Weight sharing (same filter everywhere) makes them efficient, and pooling shrinks the image step by step. ResNet (Unit 4's skip connections) dominated vision for years. Still the default on small edge devices and industrial inspection.

Vision Transformer (ViT)

Cut the image into fixed patches (e.g. 16×16 pixels), flatten each into a vector, and treat patches exactly like tokens: embeddings + positions → transformer blocks. With enough data it matches or beats CNNs, and it lets one architecture handle text and images.

Les réseaux de neurones convolutifs

Un CNN fait glisser de petits filtres appris (ex. 3×3) sur une image. Les premiers filtres détectent des bords, les suivants des textures, des parties, des objets. Le partage des poids (le même filtre partout) les rend efficaces, et le pooling réduit l’image étape par étape. ResNet (les connexions résiduelles de l’Unité 4) a dominé la vision pendant des années. Toujours le choix par défaut sur les petits appareils embarqués et en inspection industrielle.

Le Vision Transformer (ViT)

On découpe l’image en patchs fixes (ex. 16×16 pixels), on aplatit chacun en un vecteur, et on traite les patchs exactement comme des tokens : embeddings + positions → blocs de transformer. Avec assez de données, il égale ou dépasse les CNN, et une seule architecture peut traiter texte et images.

CLIP: one space for images and text

Train an image encoder and a text encoder together on 400M (image, caption) pairs. Contrastive loss: in each batch, pull the embedding of each image toward its own caption and push it away from all other captions. Result: images and text share one embedding space (Unit 6), enabling zero-shot classification ("a photo of a cracked weld" vs "a photo of a good weld") and image search by text.

Multimodal LLMs

Attach a vision encoder (often CLIP-like) to an LLM through a small projection layer that turns image features into "visual tokens" the LLM reads alongside text (LLaVA pattern; GPT-4o, Claude, Gemini, Pixtral, Qwen-VL). Audio works the same way (Whisper encodes speech).

Diffusion models

Forward process: add a little Gaussian noise over many steps until the image is pure noise (the lab slider). Reverse process: train a network to predict the noise that was added at step t; subtract it step by step, starting from random noise, to generate a new image. Conditioning on a text embedding (via cross-attention, Unit 8) steers what appears. Latent diffusion (Stable Diffusion) runs this in a compressed space for speed; newer models use transformers as the denoiser (DiT). Earlier generative approaches: GANs (generator vs discriminator game) and VAEs.

CLIP : un seul espace pour les images et le texte

On entraîne ensemble un encodeur d’images et un encodeur de texte sur 400 millions de paires (image, légende). Perte contrastive : dans chaque batch, on rapproche l’embedding de chaque image de sa propre légende et on l’éloigne de toutes les autres. Résultat : images et textes partagent un même espace d’embeddings (Unité 6), ce qui permet la classification zero-shot (« une photo d’une soudure fissurée » contre « une photo d’une bonne soudure ») et la recherche d’images par texte.

Les LLM multimodaux

On relie un encodeur de vision (souvent de type CLIP) à un LLM par une petite couche de projection qui transforme les caractéristiques de l’image en « tokens visuels » que le LLM lit avec le texte (schéma LLaVA ; GPT-4o, Claude, Gemini, Pixtral, Qwen-VL). L’audio fonctionne de la même façon (Whisper encode la parole).

Les modèles de diffusion

Processus direct : ajouter un peu de bruit gaussien sur de nombreux pas jusqu’à ce que l’image ne soit plus que du bruit (le curseur du lab). Processus inverse : entraîner un réseau à prédire le bruit ajouté au pas t ; le retirer pas à pas, en partant d’un bruit aléatoire, pour générer une nouvelle image. Conditionner sur un embedding de texte (par attention croisée, Unité 8) oriente ce qui apparaît. La diffusion latente (Stable Diffusion) fait cela dans un espace compressé pour aller plus vite ; les modèles récents utilisent des transformers comme débruiteur (DiT). Approches génératives plus anciennes : les GAN (jeu entre générateur et discriminateur) et les VAE.

Two phases

  • Prefill: process the whole prompt in parallel. Compute-heavy. Sets the time to first token (TTFT).
  • Decode: generate one token at a time (Unit 10). Sets tokens per second.

KV cache

At each decode step, the new token needs the keys and values of all previous tokens (Unit 8). Recomputing them every step is wasteful, so they are stored: the KV cache. It grows with context length × layers × heads and can take more memory than the weights for long contexts. Tricks: grouped-query attention (GQA: several query heads share one K/V head), PagedAttention (vLLM manages the cache like OS memory pages), sliding-window attention (Mistral 7B).

The memory wall

During decode, every weight must be read from memory once per token, but each weight is used for only about two operations. The GPU spends most of its time waiting for data. Decode is memory-bandwidth bound:

max tokens/s ≈ memory bandwidth (GB/s) ÷ model size in memory (GB)

A 7B model in 16-bit is 14 GB; on a 1,000 GB/s GPU that caps at about 70 tokens/s per request. Batching many users reuses each weight read for many tokens, which is why servers use continuous batching.

Quantization

Store weights with fewer bits: FP32 → FP16/BF16 → INT8 → INT4. Half the bits means half the memory and roughly double decode speed, with small quality loss down to about 4 bits.

  • Post-training quantization methods: GPTQ, AWQ (protects the most important weights), GGUF formats (Q4_K_M etc., used by llama.cpp and Ollama).
  • Quantization-aware training: simulate low precision during training for better results.
  • Pitfall: outlier values in activations; methods like SmoothQuant move them into the weights.

Deux phases

  • Prefill : traiter tout le prompt en parallèle. Gourmand en calcul. Fixe le temps jusqu’au premier token (TTFT).
  • Decode : générer un token à la fois (Unité 10). Fixe le nombre de tokens par seconde.

Le cache KV

À chaque pas de décodage, le nouveau token a besoin des clés et valeurs de tous les tokens précédents (Unité 8). Les recalculer à chaque pas est du gaspillage, donc on les stocke : c’est le cache KV. Il grandit avec longueur de contexte × couches × têtes et peut prendre plus de mémoire que les poids pour les contextes longs. Astuces : l’attention à requêtes groupées (GQA : plusieurs têtes de requête partagent une tête K/V), PagedAttention (vLLM gère le cache comme les pages mémoire d’un OS), l’attention à fenêtre glissante (Mistral 7B).

Le mur de la mémoire

Pendant le décodage, chaque poids doit être lu en mémoire une fois par token, mais n’est utilisé que pour environ deux opérations. Le GPU passe l’essentiel de son temps à attendre les données. Le décodage est limité par la bande passante mémoire :

max tokens/s ≈ memory bandwidth (GB/s) ÷ model size in memory (GB)

Un modèle 7B en 16 bits pèse 14 Go ; sur un GPU à 1 000 Go/s, cela plafonne à environ 70 tokens/s par requête. Le batching de nombreux utilisateurs réutilise chaque lecture de poids pour beaucoup de tokens : c’est pourquoi les serveurs font du batching continu.

La quantification

Stocker les poids avec moins de bits : FP32 → FP16/BF16 → INT8 → INT4. Moitié moins de bits, c’est moitié moins de mémoire et un décodage environ deux fois plus rapide, avec une petite perte de qualité jusqu’à environ 4 bits.

  • Méthodes de quantification après entraînement : GPTQ, AWQ (protège les poids les plus importants), formats GGUF (Q4_K_M etc., utilisés par llama.cpp et Ollama).
  • Entraînement conscient de la quantification (QAT) : simuler la basse précision pendant l’entraînement pour de meilleurs résultats.
  • Piège : les valeurs aberrantes (outliers) dans les activations ; des méthodes comme SmoothQuant les déplacent vers les poids.

Other speed-ups

  • FlashAttention: computes attention in tiles inside fast on-chip memory, never writing the n×n matrix to slow memory. Same result, much faster.
  • Speculative decoding: a small draft model guesses several tokens; the big model checks them all in one pass.
  • Distillation: train a small student to imitate a large teacher's outputs.
  • Pruning: remove unimportant weights or whole heads.
  • Mixture of Experts (MoE, e.g. Mixtral, DeepSeek): many FFN "experts" per layer but a router activates only 2 per token. Huge total parameters, small compute per token (still large memory).

Classic metrics

Accuracy lies when classes are imbalanced: if 1% of parts are defective, "always say OK" is 99% accurate and useless. Use the confusion matrix:

  • Precision = TP / (TP + FP): of what I flagged, how much was right.
  • Recall = TP / (TP + FN): of what was really there, how much I caught.
  • F1 = harmonic mean of the two. ROC-AUC: quality across all thresholds.

Moving the decision threshold trades one against the other. For defect detection or fraud, missing one is costly: favour recall. For spam, a false alarm is costly: favour precision.

Les métriques classiques

L’exactitude (accuracy) ment quand les classes sont déséquilibrées : si 1 % des pièces sont défectueuses, « toujours dire OK » est exact à 99 % et inutile. Utilisez la matrice de confusion :

  • Précision = VP / (VP + FP) : parmi ce que j’ai signalé, quelle part était juste.
  • Rappel = VP / (VP + FN) : parmi ce qui était vraiment là, quelle part j’ai attrapée.
  • F1 = moyenne harmonique des deux. ROC-AUC : la qualité sur tous les seuils.

Déplacer le seuil de décision échange l’un contre l’autre. Pour la détection de défauts ou de fraude, en manquer un coûte cher : privilégiez le rappel. Pour le spam, une fausse alerte coûte cher : privilégiez la précision.

Evaluating LLMs

  • Benchmarks: MMLU (knowledge), GSM8K / MATH (maths), HumanEval / SWE-bench (code), GPQA (hard science), MT-Bench and Chatbot Arena (human preference). Beware contamination: test questions leaked into training data.
  • LLM-as-a-judge: a strong model grades outputs against a rubric. Cheap and scalable, but has biases (prefers longer answers, its own style, the first option).
  • For your own product, build a golden dataset: 50–200 real questions with expected answers, run it on every change (regression testing).

MLOps: keeping models alive

  • Experiment tracking: MLflow, Weights & Biases (every run's settings, metrics, artifacts).
  • Versioning of data, code and models (DVC, model registry). Reproducibility: fixed seeds, pinned versions.
  • Deployment: containers (Docker), APIs (FastAPI), Kubernetes; CI/CD with evaluation gates.
  • Monitoring: latency, cost per request, error rates, and drift: the real-world data slowly stops looking like training data (new product line, new sensor), so performance silently decays. For LLM apps: tracing each call (LangSmith, Langfuse).

Responsible AI

  • Bias and fairness: models reproduce patterns in data (Unit 6's embedding biases). Measure performance per group.
  • Privacy: GDPR; personal data in training sets and prompts; models can memorise and leak. On-device inference (Unit 15) and anonymisation help.
  • Security: prompt injection (instructions hidden in retrieved documents or web pages), jailbreaks, data exfiltration through tools, excessive agent permissions. See the OWASP Top 10 for LLM applications.
  • Explainability: SHAP, LIME for classic models; attention maps and interpretability research for transformers.
  • EU AI Act (in force since 2024, obligations phased in 2025–2027): risk tiers (unacceptable, high, limited, minimal); high-risk systems (e.g. safety components, hiring) need risk management, data governance, documentation, human oversight; general-purpose models have transparency duties.

Évaluer des LLM

  • Benchmarks : MMLU (connaissances), GSM8K / MATH (maths), HumanEval / SWE-bench (code), GPQA (sciences difficiles), MT-Bench et Chatbot Arena (préférences humaines). Attention à la contamination : des questions de test qui ont fuité dans les données d’entraînement.
  • LLM-juge (LLM-as-a-judge) : un modèle fort note les sorties selon une grille. Peu coûteux et à grande échelle, mais biaisé (préfère les réponses longues, son propre style, la première option).

Le MLOps : garder les modèles en vie

  • Suivi des expériences : MLflow, Weights & Biases (réglages, métriques et artefacts de chaque run).
